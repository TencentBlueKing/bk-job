# 临时文件与清理

技能运行中会产生中间文件：`--*-file` 形式的 JSON 入参、待执行的脚本内容、为节省 Token 而落盘的接口输出等。本手册规定它们**放哪里**、**怎么清**，以及清理的**红线**。

## 1. 硬性规则

1. **只写技能目录下的 `tmp/`**：所有临时文件必须落在技能根目录的 [`tmp/`](../../tmp/) 子目录内，不得写到系统临时目录（`/tmp`、`%TEMP%`）、用户目录、仓库根目录或技能包内其它位置。
2. **用完必须清理**：任务结束（结论已交付给用户）时立即删除本次产生的临时文件，不留残留。
3. **清理范围只限 `tmp/` 内的内容**：**严禁**删除 `tmp/` 以外的任何目录或文件，也不要删除 `tmp/` 目录本身与其中的 `.gitignore`。

> 第 3 条是安全红线：清理命令一旦写错路径或通配符，可能删掉用户的代码或数据。**任何清理动作都必须以 `tmp/` 为根，且路径显式可见。**

## 2. 目录约定

- 位置：技能根目录下的 `tmp/`（与 `SKILL.md`、`config.yaml`、`scripts/` 同级）。
- 目录已随技能包提供，其中的 `.gitignore` 使内容不会被提交到代码库，**保留该文件**。
- 手册中的命令示例默认以**技能根目录**为工作目录，故写作 `tmp/xxx.json`。若当前工作目录不是技能根，请改用技能根的绝对路径拼接 `tmp/`，不要就近在别处新建 `tmp`。

### 2.1 命名

`tmp/<用途>-<时间戳或随机后缀>.<扩展名>`，例如：

- `tmp/exec-vars-20260804-2031.json`（`--global-vars-file` 入参）
- `tmp/plan-list-20260804-2031.json`（落盘后用 jq 分析的接口输出）
- `tmp/restart-20260804-2031.sh`（`--script-content-file` 的脚本内容）

带用途和时间戳可避免并发任务互相覆盖，也便于清理时确认归属。

**保持扁平，不要在 `tmp/` 下建子目录**：清理时只做普通删除、不递归（见第 3 节），子目录会残留下来。用文件名前缀区分归属即可。

## 3. 清理

### 3.0 清理时机：操作触发后立刻清，别等对话结束

临时文件的价值在**提交请求之前**；请求一旦发出就没有保留价值，继续堆积只会占用磁盘。

| 场景 | 清理时机 |
|------|---------|
| `--*-file` 入参（全局变量、执行目标、脚本内容等） | **写操作触发后立即清理**（拿到 `job_instance_id` 或接口返回即可），不必等用户后续追问结束 |
| **本地文件分发的上传副本** | **`upload-local-file` 上传成功后立即清理**，文件已在制品库，本地副本无保留意义；这类文件通常体积最大，最容易撑爆磁盘 |
| 落盘后用 jq/python 分析的接口输出 | 分析完、结论已提炼即可清理 |
| `--dry-run` 阶段产生的中间文件 | 若后续用户取消执行，也要清理，不要留到下次 |

失败重试时可保留入参文件复用，但**重试结束（成功或放弃）后仍要清理**。

任务收尾时再检查一遍 `tmp/`，清掉本次遗留；不确定哪些是本次产生的，可清空 `tmp/` 顶层的文件（`.gitignore` 除外）。

**清理只用普通删除：不加 `-rf`、`-Recurse`、`-Force` 等递归或强制参数。** 递归强制删除一旦路径写错就无法挽回，收益远小于风险。

**PowerShell**

```powershell
# 清理本次的具体文件（推荐，最精确）
Remove-Item tmp\exec-vars-20260804-2031.json -ErrorAction SilentlyContinue

# 清空 tmp 顶层文件，保留目录与 .gitignore；-File 保证不碰任何目录
# 注意：Get-ChildItem 的 -Exclude 在不带通配符的路径上不生效，故用 Where-Object 过滤
Get-ChildItem tmp -File | Where-Object Name -ne '.gitignore' | Remove-Item -ErrorAction SilentlyContinue
```

**bash / zsh**

```bash
# 清理本次的具体文件
rm tmp/exec-vars-20260804-2031.json

# 清空 tmp 顶层文件，保留目录与 .gitignore；-type f 保证不碰任何目录
find tmp -mindepth 1 -maxdepth 1 -type f ! -name .gitignore -exec rm {} +
```

### 3.1 删不掉就不删

文件被占用、权限不足、或残留的是目录（`rm` 不删目录）时，**保持原样即可**：

- **不要**改用 `rm -rf`、`Remove-Item -Recurse -Force` 等强制手段，也**不要**扩大删除范围重试。
- 清理失败不阻塞任务交付；在交付结论时**顺带告知用户** `tmp/` 下还有哪些文件未能清理，由用户自行处理。
- 下次任务照常继续，不必因残留文件而中断。

## 4. 禁止事项

| 禁止 | 说明 |
|------|------|
| 写入 `/tmp`、`%TEMP%` 等系统临时目录 | 不受本技能管理，可能与其它程序冲突且难以追溯 |
| 在仓库根、技能包其它目录或用户目录下建临时文件 | 会污染代码库工作区，可能被误提交 |
| 清理路径不以 `tmp/` 开头 | 一律视为违规，无论看起来多安全 |
| `rm -rf`、`Remove-Item -Recurse -Force` 等递归强制删除 | **严禁**，无论路径是否以 `tmp/` 开头；删不掉就交给用户处理 |
| 不带 `tmp/` 前缀的通配删除（如 `rm *`） | 极易误删工作区，**严禁** |
| 删除 `tmp/` 目录本身或其中的 `.gitignore` | 目录需保留供后续使用 |
| 把接口原始输出长期留在 `tmp/` 当缓存 | 数据可能过期误导后续判断；需要复用时重新查询 |

## 5. 与其它规则的关系

- **JSON 参数走文件**：内联 JSON 在 PowerShell 等环境易转义失败，各写操作的 `--*-file` 入参就是为此设计，这类文件同样受本手册约束。
- **节省 Token 的落盘分析**：将接口输出写入文件再用 `jq` 过滤的做法见 [listing-and-token-efficient-analysis.md](listing-and-token-efficient-analysis.md)，输出文件也必须落在 `tmp/`。
- **本地文件分发**：`upload-local-file` 上传的是**用户给定的源文件**，不是临时文件，不要在清理时删除用户的原始文件；见 [file-transfer.md](file-transfer.md)。
- **不要与目标机路径混淆**：`--file-target-path /tmp/`、`--server-file-list /data/...` 等指的是**作业目标机或源机上的路径**，由用户或业务决定，既不受本手册约束，也**绝不能**被清理动作触及。
